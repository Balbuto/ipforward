# Участие в разработке

Спасибо за интерес к проекту. Ниже — короткая процедура, чтобы правки проходили
быстро и без сюрпризов.

## Прежде чем начать

- Скрипт работает с iptables и требует root на боевых серверах. Тесты — нет:
  набор `tests/run-tests.sh` полностью rootless и подменяет системные утилиты
  заглушками.
- Для правок логики (создание/удаление правил, откат, блокировки) нужен тест,
  который падает до изменения и проходит после.
- Правки документации и опечаток можно отправлять без теста.

## Окружение

| Компонент | Версия | Зачем |
|-----------|--------|-------|
| bash | 4.3+ | целевая среда, скрипт не должен требовать bash 5 |
| shellcheck | 0.9+ | статический анализ (в CI — 0.10.0) |
| iptables | любые (legacy/nft) | только для ручной проверки на тестовом VPS |

Ubuntu/Debian:

```bash
sudo apt update && sudo apt install -y shellcheck
```

## Локальная проверка

```bash
git clone https://github.com/Balbuto/ipforward.git
cd ipforward

# 1. Синтаксис
bash -n ipforward.sh

# 2. Статический анализ
shellcheck -S warning ipforward.sh tests/run-tests.sh

# 3. Тесты (64 проверки, root не нужен)
bash tests/run-tests.sh

# 4. Один тест, если разбираетесь с конкретным поведением
RUN_TESTS=test_custom bash tests/run-tests.sh

# 5. Оставить временную директорию с mock-окружением и логом вызовов
KEEP_TMP=1 bash tests/run-tests.sh
```

`KEEP_TMP=1` печатает путь к каталогу `/tmp/ipforward-tests.XXXXXX`, в котором
лежат: `calls.log` (журнал вызовов mock-утилит), `rules/rules` (состояние
таблиц), `backups/`, сгенерированная `ipforward-lib.sh`.

### Как устроены тесты

- `_write_mocks` создаёт заглушки `iptables`, `iptables-save`, `ss`, `nc`,
  `netfilter-persistent`, `ufw`, `modprobe`, `sysctl` в `$TEST_TMP/bin` и ставит
  этот каталог первым в `PATH`.
- Состояние таблиц хранится строками `TABLE|CHAIN|RULE` в `$TEST_TMP/rules/rules`,
  поэтому `-C` и `-D` работают по-настоящему.
- `_load_lib` копирует `ipforward.sh` во временный файл, подменяет пути
  (`/root/iptables-backups`, `/var/run/`, `/var/log/...`) и подгружает функции
  без запуска `main()`.
- Переменные `MOCK_FAIL_UDP_A=1` и `MOCK_FAIL_SAVE=1` имитируют отказ iptables
  и `iptables-save`, чтобы проверять откат и обработку ошибок бэкапа.
- Каждый тест выполняется в отдельном подоболочном процессе: скрипт объявляет
  константы через `declare -r`, повторный `source` в той же оболочке невозможен.

## Стиль кода

- Bash, целевая версия 4.3. Не использовать `mapfile -d`, `${var@Q}` и прочие
  возможности bash 4.4+.
- Всегда `[[ ]]`, всегда `local` в функциях, кавычки вокруг подстановок.
- iptables вызывается как `iptables -w ...`; для `PREROUTING`/`POSTROUTING`
  обязательно указывать `-t nat`.
- Новые исправления помечаются комментарием `FIX #N` и получают раздел
  в `docs/AUDIT.md` и запись в `CHANGELOG.md`.
- Сообщения пользователю — по-русски, код и комментарии в коде — допустимы
  оба языка, но в пределах файла придерживайтесь существующего стиля.

## Коммиты

[Conventional Commits](https://www.conventionalcommits.org/ru/):

```plain
fix(backup): не оставлять пустой файл при сбое iptables-save
feat(cli): флаг --raw для list
docs: описать процедуру отката
test: покрыть удаление правила с диапазоном портов
```

В теле коммита укажите, какой дефект закрывается (`Refs: FIX #25`, `Closes #12`).

## Pull request

1. Ветка от `main`: `fix/<кратко>`, `feat/<кратко>`, `docs/<кратко>`.
2. В описании PR: что было не так, как воспроизвести, что изменилось.
3. Чек-лист (заполняется в шаблоне PR):
   - [ ] `bash -n ipforward.sh` без ошибок;
   - [ ] `shellcheck -S warning ipforward.sh tests/run-tests.sh` чисто;
   - [ ] `bash tests/run-tests.sh` — все проверки проходят;
   - [ ] для новой логики добавлен тест;
   - [ ] `CHANGELOG.md` обновлён.
4. Если меняется поведение правил — приложите вывод `ipforward diag` и
   `iptables -t nat -L PREROUTING -n -v` с тестового сервера.

## Чего делать не нужно

- Не переформатируйте файл целиком: `ipforward.sh` — один большой скрипт,
  тотальный рефакторинг делает диффы непроверяемыми. Разбиение на модули —
  отдельная задача, обсудите её в issue.
- Не добавляйте внешние зависимости (python, jq, curl в обязательном порядке).
  Скрипт должен работать на минимальном Debian/Ubuntu.
- Не меняйте формат бэкапов и имена цепочек — на них опирается восстановление.

## Сообщения об ошибках

Шаблон: [`.github/ISSUE_TEMPLATE/bug_report.yml`](.github/ISSUE_TEMPLATE/bug_report.yml).
Приложите версию (`ipforward --version`), дистрибутив, вывод `ipforward diag`
и шаги воспроизведения. Уязвимости — не через issue, а по [SECURITY.md](SECURITY.md).
