## [1.1.0] — 2026-11-24

Крупное исправление надёжности. Формат создаваемых правил iptables не изменился,
поэтому обновление сводится к замене файла — существующие правила продолжают
работать. Полный разбор каждого дефекта — в [docs/AUDIT.md](docs/AUDIT.md).

### Добавлено

- **CLI-режим**: `--help`, `--version`, `list` (таблицей), `list --raw`
  (машиночитаемо), `diag` (диагностика окружения, код возврата 1 при проблемах).
  Неизвестная команда — код возврата 2.
- **`preflight_check`** — валидация параметров, проверка конфликтов DNAT и
  занятости порта выполняются до создания бэкапа и любых изменений.
- **`find_conflicting_dnat`** — второй DNAT на тот же входящий порт с другой
  целью блокируется (`FIX #12`).
- **`add_rule_once`** — добавление правил идемпотентно: перед `-A` выполняется
  `-C`, дубли не накапливаются (`FIX #11`).
- **`rollback_applied`** — откат удаляет только созданные текущей операцией
  правила и восстанавливает прежнюю цель DNAT (`FIX #13`, `#14`).
- **`persist_rules()`** — единая точка сохранения: `netfilter-persistent`, при
  отсутствии — запись в `/etc/iptables/rules.v4`.
- **Уникальные имена бэкапов** — при совпадении секунды добавляется суффикс
  `-N.rules` (`FIX #24`).
- **Набор тестов `tests/run-tests.sh`** — 64 rootless-проверки на mock-утилитах.
- Документация: `CONTRIBUTING.md`, `SECURITY.md`, `docs/AUDIT.md`, шаблоны
  issue и PR, workflow CI.

### Исправлено

Критические (скрипт был неработоспособен):

- `validate_ip()` / `validate_target()`: `local _IFS='.'` не менял `IFS`,
  поэтому **любой** IP-адрес отклонялся и создание правила было невозможно
  (`FIX #1`).
- `validate_target()`: `$((10#...))` применялся к строке IP, вызывая
  фатальную ошибку арифметики (`FIX #2`).
- `set -e` завершал скрипт при любом отказе операции — меню закрывалось
  на «порт занят» и на отказе от перезаписи (`FIX #3`).
- EOF (Ctrl-D, пайп, `< /dev/null`) вызывал busy-loop с загрузкой CPU в 100 %
  (`FIX #4`).
- `check_port_available()`: шаблон `:::` не совпадал с выводом `ss`, из-за чего
  занятый IPv6-порт (`[::]:PORT`) считался свободным (`FIX #5`).
- `check_rule_exists()` / `delete_rule_by_params()`: `-C` без `-t nat` смотрел
  таблицу `filter`, поэтому «Перезаписать» не удалял старое правило, а
  появлялись два DNAT на один порт (`FIX #6`).
- Удаление правила с диапазоном портов рапортовало «✅ Удалено», но правило
  оставалось в таблице (`FIX #7`).
- `flush_rules()`: двойная пауза; бэкап создавался даже при ответе `n`
  (`A && B || C`) (`FIX #8`).
- `backup_rules()`: статус сбоя `iptables-save` терялся за `|| true`, на одну
  операцию создавалось 2–3 бэкапа (`FIX #9`).
- Lock-файл удалялся вторым экземпляром, из-за чего третий мог работать
  параллельно с первым (`FIX #10`).
- Повторное применение копило дубли `INPUT` / `FORWARD` / `MASQUERADE`
  (`FIX #11`).
- Разрешалось создать два DNAT на один входящий порт с разными целями; трафик
  молча уходил по первому правилу (`FIX #12`).

Серьёзные:

- «WireGuard Full»: вложенный вопрос «Перезаписать?» съедался редиректом,
  из-за чего операция ложно считалась неудачной и запускался откат (`FIX #13`).
- Откат «WireGuard Full» удалял ранее существовавшее правило пользователя
  (`FIX #14`).
- Статистика: без `-x` счётчики вида `12K` не суммировались, в `spt:` вместо
  адреса подставлялся порт (`FIX #15`).
- `parse_nat_rules()`: диапазоны `a:b` и цель без порта разбирались неверно
  (`FIX #16`).
- `configure_custom_rule`: два вопроса «Перезаписать?» подряд (`FIX #17`).
- UFW: логика ответа `n` построена на `A && B || C` (`FIX #18`).
- `is_container()` зависел от последнего звена `||`-цепочки и мог уронить
  скрипт (`FIX #19`).
- `MASQUERADE` добавлялся при каждом правиле без проверки (`FIX #20`).
- `validate_port()` падал на ведущих нулях: `08` → `value too great for base`
  (`FIX #21`).
- `prepare_system()` копировал скрипт в `/usr/local/bin` при каждом запуске
  (`FIX #22`).
- Мелочи: `clear` в non-tty, падение `log()` при недоступном `/var/log`,
  рассинхронизация версий в коде, меню и README (`FIX #23`).
- `backup_rules()` оставлял пустой файл при сбое `iptables-save` (`FIX #25`).

### Изменено

- Версия приведена к единому виду: `SCRIPT_VERSION="1.1.0"`, заголовок меню,
  баннер установки и README используют одну переменную.
- README переписан под 1.1.0: CLI, тесты, актуальные предупреждения, таблица
  файлов, устранение неполадок.
- Сообщения об ошибках больше не подавляются редиректами — пользователь видит
  причину отказа.

### Удалено

- Дублирующиеся вызовы `backup_rules` внутри `apply_iptables_rules` — теперь
  один бэкап на операцию (`FIX #9`).

## [1.0.0] — 2026-03-10

Первый публичный выпуск: интерактивное меню, проброс UDP/TCP, «WireGuard Full»
(UDP + TCP fallback), кастомные правила, список/удаление/flush, статистика,
бэкапы, блокировка параллельного запуска.
